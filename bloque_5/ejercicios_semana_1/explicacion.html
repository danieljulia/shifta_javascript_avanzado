ejercicios_simples_node

Primer contacto con Node. Los scripts se ejecutan en la terminal, no en el navegador (por eso no existe alert, pero sí console.log).

ejemplo.js

console.log("hola mundo");
Ejecutar: 
node ejemplo.js

package.json y npm start

El package.json define un script "start": "node ejemplo.js". Así se puede lanzar con npm start sin recordar el nombre del archivo.

leer.js — CommonJS con callback

const fs = require('fs');

fs.readFile('ejemplo.txt', 'utf8', (err, data) => {
    if (err) throw err;
    console.log(data);
});
console.log('Este mensaje se imprimirá antes...');

Idea clave: la lectura es asíncrona. Node lanza readFile, sigue con la siguiente línea, y cuando el archivo está leído ejecuta el callback. Por eso el segundo console.log sale antes que el contenido del archivo.

leer_2.mjs — ES Modules con async/await

import { readFile } from 'fs/promises';

async function leer_archivo() {
    try {
        const data = await readFile('ejemplo.txt', 'utf8');
        console.log(data);
    } catch (err) {
        console.error('Error leyendo el archivo:', err);
    }
}
leer_archivo();

Hace lo mismo que el anterior, pero con la versión de fs basada en promesas. await pausa la función hasta tener el resultado y try/catch gestiona los errores. La extensión .mjs le dice a Node que use import.

ejemplos_packages

CommonJS vs ES Modules

Node admite dos sistemas de módulos, y los ejemplos usan ambos:

CommonJSES Modules
Sintaxisconst x = require('x')import x from 'x'
Se activa conextensión .cjs (o .js por defecto)extensión .mjs o "type": "module" en package.json
Top-level awaitNoSí
Ejemploscowsay, figlet, node-serverchalk, axios, pdf-lib, Vite

Flujo general con cualquier package: npm init → npm install nombre → importarlo → ejecutar con node. Los packages se guardan en node_modules/ y quedan anotados en dependencies.

CJScommon_js / cowsay.cjs

const cowsay = require('cowsay');
console.log(cowsay.say({ text: "Hola shifta!" }));

Dibuja en la terminal una vaca en ASCII con el texto dentro de un bocadillo. Es el ejemplo más sencillo de require de un package externo.

Ejecutar: 
npm install cowsay
node cowsay.cjs

CJSascii_art / ascii.cjs

var figlet = require("figlet");

figlet("Hello Shifta!!", function (err, data) {
  if (err) { console.log("Something went wrong..."); console.dir(err); return; }
  console.log(data);
});

El package figlet convierte texto en letras grandes de ASCII art. Usa el patrón clásico de callback de Node: (err, data), se comprueba primero el error y luego se usa el resultado.

Ejecutar: 
npm install figlet
node ascii.cjs

ESMchalk / chalk.js

import tiza from 'chalk';

console.log(tiza.blue('Hello world!'));
console.log(tiza.red('This is an error message.'));
console.log(tiza.green('Success!'));
console.log(tiza.yellow('Warning!'));

chalk pinta el texto de la consola con colores. Desde su versión 5 es solo ESM, por eso el package.json lleva "type": "module". Fíjate en que el nombre de la importación por defecto es libre (tiza en lugar de chalk). El script dev permite ejecutarlo con npm run dev.

Ejecutar: 
npm install
npm run dev

ESMaxios / axios.mjs

Consulta la API de búsqueda de Wikipedia con axios (cliente HTTP) e imprime los resultados en la consola.

const response = await axios.get(url, {
  params,   // action, format, list:'search', srsearch: query...
  headers: { 'User-Agent': 'shifta2024-axios-example/1.0 (...)' }
});
const searchResults = response.data.query.search;

searchResults.forEach((result, index) => {
  console.log(`${index + 1}. ${result.title}`);
  console.log(result.snippet.replace(/<[^>]+>/g, '') + '...');
  console.log(`https://en.wikipedia.org/wiki/${encodeURIComponent(result.title)}`);
});
  • params se convierte automáticamente en la query string de la URL.
  • Wikipedia devuelve el snippet con etiquetas HTML; la expresión regular /<[^>]+>/g las elimina.
  • encodeURIComponent escapa espacios y caracteres especiales en la URL.
  • El error se lee con error.response?.status (optional chaining) porque si no hubo respuesta, response no existe.

El propio código deja un ejercicio: mostrar los resultados en un HTML en lugar de la consola. Es justo lo que hace el ejemplo ejemplos_vite/wikipedia.

Ejecutar: 
npm install
node axios.mjs

ESMpdf / pdf-lib

Crea un PDF desde JavaScript con pdf-lib. Hay dos versiones del mismo código:

ArchivoEntornoCómo entrega el PDF
pdf.jsNodewriteFileSync('output.pdf', pdfBytes) — guarda un archivo
pdf_2.js + index.htmlNavegadorCrea un Blob, una URL con URL.createObjectURL y lo muestra en un <iframe>

Pasos comunes: PDFDocument.create() → embedFont(...) → addPage() → drawText(...) → save(), que devuelve un Uint8Array con los bytes del PDF.

const blob = new Blob([pdfBytes], { type: 'application/pdf' });
const url  = URL.createObjectURL(blob);
const iframe = document.createElement('iframe');
iframe.src = url;
document.body.appendChild(iframe);
Node: 
npm init
npm i pdf-lib      # y añadir "type": "module" al package.json
node pdf.js        # genera output.pdf
Navegador: pdf_2.js usa import de un package, así que necesita un bundler (por ejemplo Vite): npx vite.

CJSnode-server / server.js

Una pequeña API REST con Express. Es el ejemplo más completo de Node de la carpeta.

Packages

PackagePara qué sirve
expressFramework para definir rutas y middleware
helmetAñade cabeceras HTTP de seguridad
corsPermite peticiones desde otros orígenes (dominios/puertos)
morganLog de cada petición en la consola
dotenvCarga .env en process.env

Middleware

Cada petición atraviesa en orden una cadena de funciones (req, res, next). Cada una puede modificar la petición, responder, o llamar a next() para pasar a la siguiente.

app.use(helmet());
app.use(cors());
app.use(morgan('combined'));
app.use(express.json());                          // lee body JSON
app.use(express.urlencoded({ extended: true }));  // lee body de formularios
app.use(requestLogger);                           // middleware propio

Autenticación con API key

const authenticateUser = (req, res, next) => {
  const apiKey = req.get('X-API-Key');
  if (!apiKey || apiKey !== process.env.API_KEY) {
    return res.status(401).json({ error: 'Unauthorized' });
  }
  next();
};

Se usa poniéndolo como segundo argumento de una ruta: app.get('/users', authenticateUser, handler).

Rutas

Método y rutaProtegidaRespuesta
GET /NoJSON de bienvenida con versión y fecha
GET /usersSíLista fija de usuarios
POST /usersSí201 con el usuario creado; 400 si faltan name o email
Cualquier otra—404 "Route not found"

Al final hay un middleware de errores (4 parámetros: err, req, res, next) que devuelve un 500, y un manejador de SIGTERM para el cierre ordenado.

Configurar .env y ejecutar: 
API_KEY=272727
PORT=27000

npm install express helmet cors morgan dotenv
node server.js

# ruta pública
curl localhost:27000/

# ruta protegida
curl -H "X-API-Key: 272727" localhost:27000/users

# crear usuario
curl -X POST -H "X-API-Key: 272727" -H "Content-Type: application/json" \
     -d '{"name":"Carla","email":"c@x.com"}' localhost:27000/users

ejemplos_vite

¿Qué es Vite y por qué se usa?

En el navegador no se puede hacer import axios from 'axios' directamente, porque el navegador no sabe buscar en node_modules. Vite es una herramienta que:

  • Sirve el proyecto en desarrollo con recarga instantánea (npm run dev).
  • Resuelve los import de packages de npm.
  • Genera una versión optimizada para producción en dist/ (npm run build) y permite probarla con npm run preview.

Los cuatro proyectos comparten los mismos scripts dev, build y preview, y el HTML carga el JS con <script type="module" src="...">.

En cualquiera de los proyectos: 
npm install
npm run dev

ejemplos_vite / simple

El proyecto mínimo: un index.html con títulos y un index.js con console.log("hola mundo"). Sirve para comprobar que Vite funciona: al abrirlo, el mensaje aparece en la consola del navegador (F12), no en la terminal.

ejemplos_vite / thecatapi

Muestra 10 fotos de gatos de TheCatAPI.

const apiKey = import.meta.env.VITE_CAT_API_KEY;   // viene del archivo .env
const url_api = "https://api.thecatapi.com/v1/images/search";

axios.get(url_api, { params: { limit: 10, api_key: apiKey } })
  .then(response => {
    response.data.forEach(result => {
      const img = document.createElement('img');
      img.src = result.url;
      img.alt = 'Cat Image';
      document.getElementById("fotos").appendChild(img);
    });
  })
  .catch(error => console.error('Error fetching data:', error));
  • La API key no está en el código: Vite expone las variables de .env que empiezan por VITE_ en import.meta.env. Copia .env.example a .env y pon tu clave (el .env está en .gitignore). Aun así, en frontend la clave acaba siendo visible en el navegador.
  • Usa promesas con .then/.catch (frente a async/await de otros ejemplos; hacen lo mismo).
  • Por cada resultado crea un <img> con createElement y lo añade al <div id="fotos">.
  • El CSS fija el ancho a 400px y usa object-fit: cover para que las imágenes no se deformen.

ejemplos_vite / wikipedia

Es la solución al ejercicio del ejemplo de axios en Node: un buscador de Wikipedia en la web.

Flujo

  1. El <form> no tiene JavaScript: al enviarlo, el navegador recarga la página con ?query=lo-que-escribas en la URL.
  2. getQueryParam('query') lee ese parámetro con URLSearchParams(window.location.search).
  3. Si existe, se llama a searchWikipedia(query), que hace la petición con axios.
  4. muestraResultados(data) vacía el contenedor y crea un <li> por resultado con enlace y snippet.
params: { action:'query', format:'json', list:'search',
          srsearch: query, utf8: 1, origin: '*' }

El parámetro origin: '*' es imprescindible en el navegador: activa CORS en la API de Wikipedia. En Node no hacía falta.

Diferencia con la versión de Node: aquí el snippet se inserta con innerHTML a propósito, porque Wikipedia devuelve <span class="searchmatch"> para resaltar las coincidencias.

ejemplos_vite / event-planner

La aplicación más completa: un gestor de eventos con Day.js (librería de fechas), LocalStorage y CSS moderno. Ya tiene su propio README.md detallado; aquí va el resumen de main.js.

Configuración de Day.js

import dayjs from 'dayjs';
import weekOfYear from 'dayjs/plugin/weekOfYear';
import relativeTime from 'dayjs/plugin/relativeTime';
import 'dayjs/locale/es';

dayjs.extend(weekOfYear);
dayjs.extend(relativeTime);
dayjs.locale('es');

Day.js es pequeño porque las funciones extra son plugins que se activan con extend. weekOfYear añade .week() y relativeTime añade .fromNow() ("en 3 días").

Estructura de la app

FunciónQué hace
init()Carga los eventos, pinta la información actual y la lista; arranca un setInterval de 1 s para el reloj
updateCurrentInfo()Muestra fecha/hora, día de la semana y semana del año con format()
listener de submitpreventDefault(), crea el evento (id: Date.now()), guarda, repinta, resetea el formulario
renderEvents()Filtra eventos futuros (isAfter), ordena, y genera el HTML con map(...).join('') y template literals
deleteEvent(id)Filtra el array para quitar el evento; se asigna a window para que el onclick inline del HTML lo encuentre
saveEventsToStorage() / loadEventsFromStorage()Persisten en localStorage con JSON.stringify/parse
showNotification()Crea un aviso, le añade la clase show para animarlo con CSS y lo elimina a los 3 s

Detalles interesantes

  • Al guardar no se guarda el objeto Day.js, solo id, name, date, time. Al cargar se reconstruye datetime con dayjs(...). Los objetos con métodos no sobreviven a JSON.
  • Urgencia visual: diff(now, 'day') decide la clase CSS: urgent-today (rojo), urgent-soon (naranja, ≤ 3 días) o ninguna (azul).
  • Estado + render: el array events es la única fuente de verdad; cada cambio termina llamando a renderEvents() que redibuja todo.
  • Al final hay console.log con ejemplos de Day.js para explorar en la consola del navegador.
  • vite.config.js fija el puerto 3000 y abre el navegador automáticamente.

Notas: errores corregidos

Al revisar los ejemplos se detectaron estos problemas, ya corregidos:

  • API key en el código (thecatapi): ahora se lee de .env con import.meta.env.VITE_CAT_API_KEY; se incluye .env.example. La clave antigua sigue en el historial de git, así que conviene regenerarla en TheCatAPI.
  • Readme de axios: ahora indica node axios.mjs.
  • Cierre ordenado en server.js: se guarda el resultado de app.listen() en server y se llama a server.close().
  • Orden de middleware en server.js: primero el 404 y el manejador de errores el último.
  • .env en el repositorio (node-server): se añadió .gitignore y .env.example. Como el .env ya estaba versionado, hay que ejecutar git rm --cached .env para que git deje de seguirlo.
  • HTML incompleto: simple y wikipedia ahora cierran </body>.
  • XSS en event-planner: el nombre del evento se pasa por escapeHtml() antes de usar innerHTML.
